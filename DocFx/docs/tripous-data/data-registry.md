# DataRegistry

`DataRegistry` is the central registry of the Tripous.Data layer.
It stores the definitions that describe data modules, lookups, locators, code providers, document handlers, and configuration properties.

The registry is metadata, not database data.
Applications populate it during startup, either manually or from files generated by RegBuilder.

## Registry Collections

`DataRegistry` exposes typed definition lists.

- `Modules`, for `ModuleDef`.
- `Lookups`, for `LookupDef`.
- `Locators`, for `LocatorDef`.
- `CodeProviders`, for `CodeProviderDef`.
- `DocumentHandlers`, for `DocumentHandlerDef`.
- `ConfigProperties`, for `ConfigPropertyDef`.

```csharp
ModuleDef Module = DataRegistry.Modules.Get("Customer");
LookupDef Lookup = DataRegistry.Lookups.Get("Customer");
LocatorDef Locator = DataRegistry.Locators.Get("Customer");
```

These lists are used later by `DataModule`, locators, lookup sources, configuration, and the desktop UI.

## Modules

A module definition connects a database table, a `DataModule` class, list SELECTs, fields, details, filters, and security metadata.

```csharp
string SqlText = @"
select
    Id,
    Code,
    Name
from Customer
order by Name";

ModuleDef Module = DataRegistry.AddModule(
    "Customer",
    TitleKey: "Customers",
    ClassName: typeof(CustomerDataModule).FullName,
    ListSelectSql: SqlText,
    IsSingleSelect: true);
```

The module contains the editable table definition.

```csharp
TableDef Table = Module.Table;

Table.Name = "Customer";
Table.AddId();
Table.AddString("Code", 40, Flags: FieldFlags.Required | FieldFlags.Searchable);
Table.AddString("Name", 96, Flags: FieldFlags.Required | FieldFlags.Searchable);
```

`AddModule()` throws when the module already exists.
`AddOrUpdateModule()` is used by generated registry versions because it can merge repeated registration passes.

```csharp
ModuleDef Module = DataRegistry.AddOrUpdateModule(
    "Customer",
    ClassName: "CustomerDataModule",
    ListSelectSql: SqlText);
```

When updating an existing definition, child collections are preserved.
That matters when multiple registry files extend the same module.

## Lookup List Modules

`AddLookupListModule()` creates a simple module with an `Id` and `Name` table.
It is useful for small list tables.

```csharp
ModuleDef Module = DataRegistry.AddLookupListModule(
    TableName: "PaymentMethod",
    Name: "PaymentMethod",
    TitleKey: "Payment Methods");
```

The result is a single-select module without filters.

## Lookups

Lookups describe value lists used by fields and UI editors.
The source may be an enum, a table, SQL text, or a custom class.

```csharp
DataRegistry.AddLookupSource(typeof(DocumentStatus));
```

```csharp
DataRegistry.AddLookupWithTableName(
    "Customer",
    "Customer",
    FormName: "Customer");
```

```csharp
DataRegistry.AddLookupWithSql(
    "ActiveCustomer",
    @"
select
    Id,
    Name
from Customer
where IsActive = :IsActive");
```

RegBuilder-generated code normally uses the `AddOrUpdate...` variants.

```csharp
DataRegistry.AddOrUpdateLookupWithTableName(
    "Customer",
    "Customer",
    FormName: "Customer");
```

## Locators

Locators describe search and pick behavior.
They are used when a user selects a row from another table, such as selecting a customer on an invoice.

```csharp
LocatorDef Locator = DataRegistry.AddLocator(
    "Customer",
    SourceTableName: "Customer",
    KeyField: "Id",
    FormName: "Customer");
```

A locator can also be based on explicit SQL.

```csharp
LocatorDef Locator = DataRegistry.AddLocatorWithSql(
    "ActiveCustomer",
    @"
select
    Id,
    Code,
    Name
from Customer
where IsActive = :IsActive",
    KeyField: "Id",
    FormName: "Customer");
```

After registrations, locator references are updated before data modules initialize.

```csharp
DataRegistry.UpdateLocatorReferences();
```

`DataModule.Initialize()` calls this, so ordinary module creation does not need to call it manually.

## Code Providers

Code providers define automatic document or master-data numbering.

```csharp
CodeProviderDef Provider = DataRegistry.AddOrUpdateCodeProvider("Customer");
```

A field can reference a code provider through its `FieldDef.CodeProvider`.
`DataModule` then assigns the next code inside the commit transaction.

```csharp
FieldDef Field = Module.Table.Fields.Get("Code");
Field.CodeProvider = "Customer";
```

## Document Handlers

Document handlers connect a module name with a handler class.
They are used by document-style modules for validation and posting behavior.

```csharp
DataRegistry.AddOrUpdateDocumentHandler(
    "SalesInvoice",
    typeof(SalesInvoiceDocumentHandler).FullName);
```

The document module can then find its handler through `DataRegistry.DocumentHandlers`.

## Config Properties

Configuration properties define application settings that are stored and edited through the config system.

```csharp
DataRegistry.AddConfigProperty(
    "MiniCrm.AutoOpenCustomerList",
    TitleKey: "Auto Open Customer List",
    GroupName: "Mini CRM",
    SecurityLevel: UserLevel.None,
    Kind: ConfigValueKind.Boolean,
    DefaultValue: "true");
```

Use `AddOrUpdateConfigProperty()` when generated or repeated registration should preserve the existing definition instance.

## Creating Modules

`CreateModule()` creates a `DataModule` from a registered module name.
By default, it initializes the module too.

```csharp
DataModule Module = DataRegistry.CreateModule("Customer");
```

When the module definition has a custom class name, the custom type is created.

```csharp
CustomerDataModule Module = DataRegistry.CreateModule("Customer") as CustomerDataModule;
```

This is used by application services, sample-data loaders, tests, and UI forms.

## Generated And Manual Registration

Manual registration and RegBuilder-generated registration both feed `DataRegistry`.

Manual registration is useful for small applications and custom extensions.
Generated registration is useful when the schema is the source of truth.

The generated code uses mostly `AddOrUpdate...` methods because a registry version may be split across several files:

- Modules.
- Lookups.
- Locators.
- Code providers.
- Forms.
- Document handlers.

Do not edit generated registry files directly.
Change the schema or manual extension code and regenerate the registry files when needed.

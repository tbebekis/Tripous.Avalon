tERP tester guide
=================

Purpose
-------

This guide is for the first manual testers of tERP.

Please follow the steps exactly where possible. The application contains sample data, so the names below should already exist after a fresh database is created.

When reporting an issue, send:

- The test section number.
- The exact step where it happened.
- What you expected.
- What actually happened.
- A screenshot if possible.
- The full error message if one appeared.


Basic rules for testing
-----------------------

- Use a fresh database before starting a full test pass.
- Do not skip the Save step before pressing Post Document.
- After each important action, check both the document itself and the read-only Views.
- If a button is disabled, hover it or note which document state you are in.
- If something looks wrong, do not try to fix the data manually. Report it.


Installation and first run
--------------------------

1. Download the package for your operating system:

   Windows x64:

   https://github.com/tbebekis/Tripous.Avalon/releases/download/v1.0.0/tERP.win-x64.zip

   Linux x64:

   https://github.com/tbebekis/Tripous.Avalon/releases/download/v1.0.0/tERP.linux-x64.zip

2. Unzip the release package to a normal folder.

   Example:

   C:\Temp\tERP

3. Run the tERP executable from the unzipped folder.

4. On first run, wait a few seconds until the application starts.

   The application will show a series of information boxes while it creates the database.

5. On first run, the application should create the SQLite database automatically.

6. On first run, the application will also insert the sample data and then close.

7. Run the tERP executable again.

8. After the database is created, the application will ask for the first admin user.

   Enter:

   Full name: Test Admin
   User name: admin
   Password: admin
   Culture: en-US

9. The main window should open.

10. In the top toolbar press Dashboard.

11. Expected result:

   The Dashboard tab opens without errors.


Database location and reset
---------------------------

Use this when you need to return to a clean test database.

1. Open the application.

2. Press General > ShowAppFolder.

3. The application data folder opens.

4. The SQLite database is normally:

   Data\tERP.db3

5. To regenerate the database from inside the application:

   - Press General > Regenerate Database.
   - Confirm the warning.
   - The application should say that the sample SQLite database was deleted.
   - The application closes.
   - Start the application again.

6. Expected result after restart:

   - Database is recreated.
   - Sample data is recreated.
   - Dashboard opens normally.


Toolbar buttons used in this guide
----------------------------------

Most forms use the same toolbar.

- List (F5): returns to the list.
- Refresh List (Ctrl+F5): reloads the list.
- Find (Ctrl+F): opens search/filter.
- Insert (Ctrl+Insert): creates a new item/document.
- Edit (Ctrl+Enter): edits the selected item/document.
- Delete (Ctrl+Delete): deletes the selected item/document.
- Save (Ctrl+S): saves changes.
- Cancel (Escape): cancels editing.
- Post Document: posts a saved document.
- Close: closes the form.

Document forms may also show extra buttons:

- Create Sales Delivery Note
- Create Sales Return
- Create Sales Invoice
- Create Sales Credit Note
- Create Sales Cancellation
- Create Customer Receipt
- Create Customer Receipt Cancellation
- Create Purchase Delivery Note
- Create Purchase Return
- Create Purchase Invoice
- Create Purchase Credit Note
- Create Purchase Cancellation
- Create Supplier Payment
- Create Supplier Payment Cancellation
- Create Stock Cancellation

User login tests
----------------

The application can run in two modes:

- Use Users = false: auto-login.
- Use Users = true: login dialog.

The setting is in General > Application Settings.

1. Start from a clean database.

2. Open General > Application Settings.

3. Find Application > Use Users.

4. Set Use Users to false.

5. Save the settings.

6. Close and restart the application.

7. Expected result:

   The application opens without a login dialog.

8. Open Setup > AppUser.

9. Insert a new user:

   FullName: Test User
   UserName: tester
   UserLevelId: User
   CultureCode: en-US
   Email: tester@example.com
   IsActive: true

10. Press Save.

11. Press Edit on the tester row.

12. Press Set Password.

13. Enter:

   Password: tester
   Confirm password: tester

14. Press OK.

15. Open General > Application Settings again.

16. Set Application > Use Users to true.

17. Save the settings.

18. Close and restart the application.

19. Expected result:

   The login dialog appears.

20. Login as:

   User name: tester
   Password: tester

21. Expected result:

   The application opens.

22. Check access as normal user:

   - General > Regenerate Database should not be available.
   - General > ConnectionInfo should not be available.
   - Setup > AppUser should not be available.

23. Close the application.

24. Login as admin.

25. Expected result:

   Admin-only commands are visible again.

Sales order to delivery note to invoice
---------------------------------------

Goal:

Create a Sales Order for Acme Retail SA, convert it to a Sales Delivery Note, then convert it to a Sales Invoice.

1. Open Sales > SalesOrder.

2. Press Insert.

3. Fill the header:

   PersonId: CUST-ACME / Acme Retail SA
   WarehouseId: Main Warehouse
   CurrencyId: EUR
   ExchangeRate: 1
   PaymentMethodId: Payment To Bank Account
   PaymentTermId: 30 Days
   OriginTaxJurisdictionId: GR
   DestinationTaxJurisdictionId: GR

4. In the TradeLine grid press Ctrl+Insert or the grid Add button.

5. Add line 1:

   Product: Laptop Computer 14
   Quantity: 2
   Warehouse: Main Warehouse

6. Add line 2:

   Product: Wireless Keyboard
   Quantity: 3
   Warehouse: Main Warehouse

7. Press Save.

8. Expected result:

   A document code is assigned.
   Status is Draft.

9. Press Post Document.

10. Confirm the posting question.

11. Expected result:

   Status becomes Posted.
   The document becomes locked/read-only.
   The Create Sales Delivery Note button becomes enabled.

12. Press Create Sales Delivery Note.

13. Confirm the question.

14. Expected result:

   A new Sales Delivery Note opens with the same customer and lines.

15. On the Sales Delivery Note press Save.

16. Press Post Document.

17. Confirm the posting question.

18. Expected result:

   Status becomes Posted.
   Stock is decreased.
   Create Sales Invoice and Create Sales Return buttons become enabled.

19. Open Views > Stock Movements.

20. Filter DocumentCode by the Sales Delivery Note code.

21. Expected result:

   Two stock movements exist.
   Laptop Computer 14 has Direction = Out and Quantity = 2.
   Wireless Keyboard has Direction = Out and Quantity = 3.

22. Open Views > Stock Balance.

23. Check:

   Laptop Computer 14 / Main Warehouse decreased from 50 to 48.
   Wireless Keyboard / Main Warehouse decreased from 150 to 147.

24. Return to the posted Sales Delivery Note.

25. Press Create Sales Invoice.

26. Confirm the question.

27. Expected result:

   A new Sales Invoice opens with the same customer and lines.

28. Press Save.

29. Press Post Document.

30. Confirm the posting question.

31. Expected result:

   Status becomes Posted.
   Create Customer Receipt, Create Sales Credit Note and Create Sales Cancellation buttons become enabled.

32. Open Views > Trade Documents.

33. Filter PartnerCode by CUST-ACME.

34. Expected result:

   Sales Order, Sales Delivery Note and Sales Invoice are visible and Posted.

35. Open Views > Finance Movements.

36. Filter DocumentCode by the Sales Invoice code.

37. Expected result:

   One Person movement exists for CUST-ACME.
   TradeType = Sales.
   Direction = In.

38. Open Views > Journal Entries.

39. Filter DocumentCode by the Sales Invoice code.

40. Expected result:

   One posted Journal Entry exists.

- Sales Delivery Note can be created from Sales Order.
- Sales Return can be created from Sales Delivery Note.
- Sales Invoice can be created from Sales Delivery Note.
- Customer Receipt can be created from Sales Invoice.
- Customer Receipt Cancellation reverses the receipt.
- Sales Credit Note can be created from Sales Invoice.
- Sales Cancellation can be created only when no Credit Note exists.
- Purchase Order can be posted.
- Purchase Delivery Note can be created from Purchase Order.
- Purchase Return can be created from Purchase Delivery Note.
- Purchase Invoice can be created from Purchase Delivery Note.
- Supplier Payment can be created from Purchase Invoice.
- Supplier Payment Cancellation reverses the payment.
- Purchase Credit Note can be created from Purchase Invoice.
- Purchase Cancellation can be created only when no Credit Note exists.
- Stock Receipt increases stock.
- Stock Issue decreases stock.
- Stock Transfer moves stock between warehouses.
- Stock Cancellation reverses a stock trade.
- Invalid negative stock is rejected.
- Manual balanced Journal Entry can be posted.
- Manual unbalanced Journal Entry is rejected.
- Read-only views open and filter correctly.
- Regenerate Database deletes the database and closes the application.

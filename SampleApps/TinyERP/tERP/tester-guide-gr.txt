Οδηγός ελέγχου tERP
===================

Σκοπός
------

Αυτός ο οδηγός είναι για τους πρώτους χειροκίνητους ελέγχους του tERP.

Ακολουθήστε τα βήματα όσο γίνεται ακριβώς. Η εφαρμογή περιέχει sample data, άρα τα ονόματα που αναφέρονται παρακάτω πρέπει να υπάρχουν ήδη μετά τη δημιουργία μίας καθαρής βάσης.

Όταν αναφέρετε πρόβλημα, στείλτε:

- Τον τίτλο της ενότητας.
- Το ακριβές βήμα όπου εμφανίστηκε το πρόβλημα.
- Τι περιμένατε να συμβεί.
- Τι συνέβη πραγματικά.
- Screenshot, αν είναι δυνατόν.
- Το πλήρες μήνυμα λάθους, αν εμφανίστηκε.


Βασικοί κανόνες ελέγχου
-----------------------

- Ξεκινήστε ένα πλήρες test pass με καθαρή βάση.
- Μην παραλείπετε το Save πριν από το Post Document.
- Μετά από κάθε σημαντική ενέργεια, ελέγχετε και το ίδιο το παραστατικό και τα read-only Views.
- Αν ένα κουμπί είναι ανενεργό, σημειώστε σε ποιο παραστατικό και σε ποια κατάσταση βρίσκεστε.
- Αν κάτι φαίνεται λάθος, μην διορθώσετε χειροκίνητα τα δεδομένα. Αναφέρετέ το.


Εγκατάσταση και πρώτη εκκίνηση
------------------------------

1. Κάντε unzip το release package σε έναν απλό φάκελο.

   Παράδειγμα:

   C:\Temp\tERP

2. Εκτελέστε το tERP executable από τον φάκελο που έγινε unzip.

3. Στην πρώτη εκκίνηση, η εφαρμογή πρέπει να δημιουργήσει αυτόματα τη SQLite database.

4. Αν η εφαρμογή ζητήσει τον πρώτο admin χρήστη, βάλτε:

   Full name: Test Admin
   User name: admin
   Password: admin
   Culture: en-US

5. Πρέπει να ανοίξει το κύριο παράθυρο.

6. Στο επάνω toolbar πατήστε Dashboard.

7. Αναμενόμενο αποτέλεσμα:

   Ανοίγει το Dashboard tab χωρίς λάθη.


Τοποθεσία βάσης και επαναδημιουργία
-----------------------------------

Χρησιμοποιήστε αυτό όταν θέλετε να γυρίσετε σε καθαρή test database.

1. Ανοίξτε την εφαρμογή.

2. Πατήστε General > ShowAppFolder.

3. Ανοίγει ο φάκελος δεδομένων της εφαρμογής.

4. Η SQLite database είναι συνήθως:

   Data\tERP.db3

5. Για επαναδημιουργία της βάσης μέσα από την εφαρμογή:

   - Πατήστε General > Regenerate Database.
   - Επιβεβαιώστε το warning.
   - Η εφαρμογή πρέπει να εμφανίσει μήνυμα ότι η sample SQLite database διαγράφηκε.
   - Η εφαρμογή κλείνει.
   - Ξεκινήστε ξανά την εφαρμογή.

6. Αναμενόμενο αποτέλεσμα μετά την επανεκκίνηση:

   - Η βάση δημιουργείται ξανά.
   - Τα sample data δημιουργούνται ξανά.
   - Το Dashboard ανοίγει κανονικά.


Κουμπιά toolbar που χρησιμοποιούνται στον οδηγό
-----------------------------------------------

Οι περισσότερες φόρμες έχουν το ίδιο toolbar.

- List (F5): επιστροφή στη λίστα.
- Refresh List (Ctrl+F5): ανανέωση λίστας.
- Find (Ctrl+F): αναζήτηση/filter.
- Insert (Ctrl+Insert): δημιουργία νέας εγγραφής ή παραστατικού.
- Edit (Ctrl+Enter): επεξεργασία επιλεγμένης εγγραφής ή παραστατικού.
- Delete (Ctrl+Delete): διαγραφή επιλεγμένης εγγραφής ή παραστατικού.
- Save (Ctrl+S): αποθήκευση αλλαγών.
- Cancel (Escape): ακύρωση επεξεργασίας.
- Post Document: οριστικοποίηση/καταχώριση αποθηκευμένου παραστατικού.
- Close: κλείσιμο φόρμας.

Οι φόρμες παραστατικών μπορεί να εμφανίζουν και επιπλέον κουμπιά:

- Create Sales Delivery Note
- Create Sales Return
- Create Sales Invoice
- Create Sales Credit Note
- Create Sales Cancellation
- Create Customer Receipt
- Create Customer Receipt Cancellation
- Create Purchase Delivery Note
- Create Purchase Return
- Create Purchase Invoice
- Create Purchase Credit Note
- Create Purchase Cancellation
- Create Supplier Payment
- Create Supplier Payment Cancellation
- Create Stock Cancellation

Έλεγχοι login χρηστών
---------------------

Η εφαρμογή μπορεί να λειτουργήσει σε δύο modes:

- Use Users = false: αυτόματο login.
- Use Users = true: εμφανίζεται login dialog.

Η ρύθμιση βρίσκεται στο General > Application Settings.

1. Ξεκινήστε από καθαρή βάση.

2. Ανοίξτε General > Application Settings.

3. Βρείτε Application > Use Users.

4. Θέστε Use Users σε false.

5. Πατήστε Save.

6. Κλείστε και ξανανοίξτε την εφαρμογή.

7. Αναμενόμενο αποτέλεσμα:

   Η εφαρμογή ανοίγει χωρίς login dialog.

8. Ανοίξτε Setup > AppUser.

9. Δημιουργήστε νέο χρήστη:

   FullName: Test User
   UserName: tester
   UserLevelId: User
   CultureCode: en-US
   Email: tester@example.com
   IsActive: true

10. Πατήστε Save.

11. Πατήστε Edit στη γραμμή του tester.

12. Πατήστε Set Password.

13. Συμπληρώστε:

   Password: tester
   Confirm password: tester

14. Πατήστε OK.

15. Ανοίξτε ξανά General > Application Settings.

16. Θέστε Application > Use Users σε true.

17. Πατήστε Save.

18. Κλείστε και ξανανοίξτε την εφαρμογή.

19. Αναμενόμενο αποτέλεσμα:

   Εμφανίζεται login dialog.

20. Κάντε login ως:

   User name: tester
   Password: tester

21. Αναμενόμενο αποτέλεσμα:

   Η εφαρμογή ανοίγει.

22. Ελέγξτε πρόσβαση ως απλός User:

   - Το General > Regenerate Database δεν πρέπει να είναι διαθέσιμο.
   - Το General > ConnectionInfo δεν πρέπει να είναι διαθέσιμο.
   - Το Setup > AppUser δεν πρέπει να είναι διαθέσιμο.

23. Κλείστε την εφαρμογή.

24. Κάντε login ως admin.

25. Αναμενόμενο αποτέλεσμα:

   Τα admin-only commands εμφανίζονται ξανά.

Sales Order σε Delivery Note και Invoice
----------------------------------------

Στόχος:

Δημιουργία Sales Order για Acme Retail SA, μετατροπή σε Sales Delivery Note και μετά σε Sales Invoice.

1. Ανοίξτε Sales > SalesOrder.

2. Πατήστε Insert.

3. Συμπληρώστε header:

   PersonId: CUST-ACME / Acme Retail SA
   WarehouseId: Main Warehouse
   CurrencyId: EUR
   ExchangeRate: 1
   PaymentMethodId: Payment To Bank Account
   PaymentTermId: 30 Days
   OriginTaxJurisdictionId: GR
   DestinationTaxJurisdictionId: GR

4. Στο grid TradeLine πατήστε Ctrl+Insert ή το κουμπί Add του grid.

5. Προσθέστε γραμμή 1:

   Product: Laptop Computer 14
   Quantity: 2
   Warehouse: Main Warehouse

6. Προσθέστε γραμμή 2:

   Product: Wireless Keyboard
   Quantity: 3
   Warehouse: Main Warehouse

7. Πατήστε Save.

8. Αναμενόμενο αποτέλεσμα:

   Δίνεται document code.
   Το status είναι Draft.

9. Πατήστε Post Document.

10. Επιβεβαιώστε την ερώτηση.

11. Αναμενόμενο αποτέλεσμα:

   Το status γίνεται Posted.
   Το παραστατικό κλειδώνει/read-only.
   Το κουμπί Create Sales Delivery Note ενεργοποιείται.

12. Πατήστε Create Sales Delivery Note.

13. Επιβεβαιώστε την ερώτηση.

14. Αναμενόμενο αποτέλεσμα:

   Ανοίγει νέο Sales Delivery Note με τον ίδιο πελάτη και τις ίδιες γραμμές.

15. Στο Sales Delivery Note πατήστε Save.

16. Πατήστε Post Document.

17. Επιβεβαιώστε την ερώτηση.

18. Αναμενόμενο αποτέλεσμα:

   Το status γίνεται Posted.
   Το stock μειώνεται.
   Τα κουμπιά Create Sales Invoice και Create Sales Return ενεργοποιούνται.

19. Ανοίξτε Views > Stock Movements.

20. Φιλτράρετε DocumentCode με τον κωδικό του Sales Delivery Note.

21. Αναμενόμενο αποτέλεσμα:

   Υπάρχουν δύο stock movements.
   Το Laptop Computer 14 έχει Direction = Out και Quantity = 2.
   Το Wireless Keyboard έχει Direction = Out και Quantity = 3.

22. Ανοίξτε Views > Stock Balance.

23. Ελέγξτε:

   Laptop Computer 14 / Main Warehouse μειώθηκε από 50 σε 48.
   Wireless Keyboard / Main Warehouse μειώθηκε από 150 σε 147.

24. Επιστρέψτε στο posted Sales Delivery Note.

25. Πατήστε Create Sales Invoice.

26. Επιβεβαιώστε την ερώτηση.

27. Αναμενόμενο αποτέλεσμα:

   Ανοίγει νέο Sales Invoice με τον ίδιο πελάτη και τις ίδιες γραμμές.

28. Πατήστε Save.

29. Πατήστε Post Document.

30. Επιβεβαιώστε την ερώτηση.

31. Αναμενόμενο αποτέλεσμα:

   Το status γίνεται Posted.
   Τα κουμπιά Create Customer Receipt, Create Sales Credit Note και Create Sales Cancellation ενεργοποιούνται.

32. Ανοίξτε Views > Trade Documents.

33. Φιλτράρετε PartnerCode με CUST-ACME.

34. Αναμενόμενο αποτέλεσμα:

   Sales Order, Sales Delivery Note και Sales Invoice είναι ορατά και Posted.

35. Ανοίξτε Views > Finance Movements.

36. Φιλτράρετε DocumentCode με τον κωδικό του Sales Invoice.

37. Αναμενόμενο αποτέλεσμα:

   Υπάρχει ένα Person movement για CUST-ACME.
   TradeType = Sales.
   Direction = In.

38. Ανοίξτε Views > Journal Entries.

39. Φιλτράρετε DocumentCode με τον κωδικό του Sales Invoice.

40. Αναμενόμενο αποτέλεσμα:

   Υπάρχει ένα posted Journal Entry.

   Το UnappliedAmount είναι 0.

11. Αναμενόμενο αποτέλεσμα:

   Υπάρχουν δύο movements:

   - Person movement για CUST-ACME, TradeType = Sales, Direction = Out.
   - Bank movement, TradeType = Financial, Direction = In.

13. Αναμενόμενο αποτέλεσμα:

   Το Bank balance αυξήθηκε κατά το ποσό της είσπραξης.

15. Πατήστε Create Customer Receipt Cancellation.

16. Επιβεβαιώστε την ερώτηση.

17. Αναμενόμενο αποτέλεσμα:

   Ανοίγει Customer Receipt Cancellation.
   Δεν έχει settlement rows.

18. Πατήστε Save.

19. Πατήστε Post Document.

20. Αναμενόμενο αποτέλεσμα:

   Το αρχικό Customer Receipt γίνεται Cancelled.
   Το cancellation document γίνεται Posted.
   Το Bank balance επιστρέφει στην τιμή πριν από την είσπραξη.

   Customer: CUST-ACME / Acme Retail SA

   Quantity: 5

6. Πατήστε Save και Post στο Sales Delivery Note.

7. Πατήστε Create Sales Invoice.

16. Αναμενόμενο αποτέλεσμα:

   Το Sales Credit Note γίνεται Posted.
   Δημιουργεί finance και accounting reversal movements.
   Δεν δημιουργεί stock movements.

18. Φιλτράρετε DocumentCode με τον κωδικό του Sales Credit Note.

19. Αναμενόμενο αποτέλεσμα:

   Δεν υπάρχει stock movement για το Sales Credit Note.

Regression checklist
--------------------

Πριν ολοκληρώσετε ένα πλήρες test pass, επιβεβαιώστε τα εξής:

- Μπορεί να δημιουργηθεί καθαρή βάση.
- Τα sample data δημιουργούνται.
- Το auto-login mode δουλεύει.
- Το login mode δουλεύει.
- Τα admin-only commands κρύβονται από απλούς users.
- Sales Order μπορεί να γίνει posted.
- Sales Delivery Note μπορεί να δημιουργηθεί από Sales Order.
- Sales Return μπορεί να δημιουργηθεί από Sales Delivery Note.
- Sales Invoice μπορεί να δημιουργηθεί από Sales Delivery Note.
- Customer Receipt μπορεί να δημιουργηθεί από Sales Invoice.
- Customer Receipt Cancellation αντιστρέφει την είσπραξη.
- Sales Credit Note μπορεί να δημιουργηθεί από Sales Invoice.
- Sales Cancellation μπορεί να δημιουργηθεί μόνο όταν δεν υπάρχει Credit Note.
- Purchase Order μπορεί να γίνει posted.
- Purchase Delivery Note μπορεί να δημιουργηθεί από Purchase Order.
- Purchase Return μπορεί να δημιουργηθεί από Purchase Delivery Note.
- Purchase Invoice μπορεί να δημιουργηθεί από Purchase Delivery Note.
- Supplier Payment μπορεί να δημιουργηθεί από Purchase Invoice.
- Supplier Payment Cancellation αντιστρέφει την πληρωμή.
- Purchase Credit Note μπορεί να δημιουργηθεί από Purchase Invoice.
- Purchase Cancellation μπορεί να δημιουργηθεί μόνο όταν δεν υπάρχει Credit Note.
- Stock Receipt αυξάνει το stock.
- Stock Issue μειώνει το stock.
- Stock Transfer μεταφέρει stock μεταξύ warehouses.
- Stock Cancellation αντιστρέφει stock trade.
- Invalid negative stock απορρίπτεται.
- Χειροκίνητο balanced Journal Entry μπορεί να γίνει posted.
- Χειροκίνητο unbalanced Journal Entry απορρίπτεται.
- Τα read-only views ανοίγουν και φιλτράρουν σωστά.
- Το Regenerate Database διαγράφει τη βάση και κλείνει την εφαρμογή.
